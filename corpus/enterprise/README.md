# Enterprise equipment-service seed pack

E0 source generation is local. On 2026-09-11, the archived25-PDF packet was
published to the private Azure Blob `certificate-sources` container. A live
read-only E1 probe extracted the DEMO-PT-001 service/certificate PDFs using
Document Intelligence and passed their evidence to all three hosted specialists.
This is not customer-release acceptance or a Foundry IQ/vector-index integration.

From the repository root, with existing Python/Node dependencies installed:

```powershell
$env:UV_CACHE_DIR = "$PWD\.uv-cache"
node src/web/scripts/render-enterprise-demo.mjs 2026-09-10
```

Uses the existing Playwright/Edge installation, no external page or image loading.
Creates a fresh `.test-artifacts/enterprise-<date>-<unique>/` directory containing
25 PDFs, `catalog.json`, SHA-256 `manifest.json`, and a contract layout preview.
Never overwrites previous artifacts. The explicit seed date makes source records
reproducible; browser-generated PDF bytes may differ because of creation metadata.
Archive the exact generated bytes/hash manifest used by a future Run.

Definitions: `innexq_gateway.demo_catalog`, `innexq_gateway.demo_documents`.
Schema: `src/contracts/schemas/v1/enterprise-demo-catalog.schema.json`.

Six contracts belong to Fabrikam, Northwind and Alpine (two each). The new Fabrikam
portfolio has four pallet trucks, not the separate legacy 18-compressor contract.
Sales records contain invoices and credit notes, not cached approval decisions.
Under the proposed, not-yet-approved sales definition, they demonstrate above,
below and exactly-at-threshold conditions. Presets contain only customer requests.

All documents are fictional, unsigned and clearly marked. A generated certificate
does not establish authenticity, operational safety, eligibility or delivery access.
The extraction pipeline reads the PDFs and validates its findings independently;
the seed generator is never a substitute for Document Intelligence.

## E1 private source publication

`uv run python scripts/seed_certificates.py --help` describes the create-only
publisher. Its default dry run validates the exact catalog, manifest and all PDFs.
Use the explicit `--upload` option only after the private `certificate-sources`
container and scoped deployment identity grant are provisioned. Authentication
uses Azure CLI/Entra, never an account key or SAS. Publish the archived packet;
do not regenerate dates or bytes to make an expired case pass.

PDFs are stored under content-addressed SHA-256 paths, and the authoritative
registry is published last. Existing blobs must be byte-identical; neither PDFs
nor registry are silently overwritten. The registry explicitly authors fictional
revocation/in-service states, not OCR output. Document Intelligence independently
extracts the source PDFs during actual requests. A successful upload is not proof
of extraction, customer eligibility, release or Teams notification.
